**Status:** Current-source audit against `origin/main` 5a083d6; no product behaviour changed

**Scope:** All 35 route kinds in `src/ui/route.ts`

## Method and evidence limits

- Each route kind was traced from `src/ui/route.ts` through the `App.tsx` render mapping to its component and file. Verdicts cite file and line.
- Raw controls, hand-rolled status markup, `SortableTable` heading levels, `PageHeader` basis props, hard-coded shadows and backdrops, and device-setting keys were located by grep. Each finding was re-read in its file before it was recorded. Findings that could not be confirmed were dropped; see "Corrections to the research digest".
- Viewport, dark-mode, focus, zoom, contrast and safe-area checks need a browser. They are listed under "Not verified in browser" and are not counted as pass or fail.
- Verdicts are per route, not per component. A component shared by several routes is cited once and its verdict applies to each route it serves.

Notes on the table:

- **§2 basis line.** Every calculated person route above passes `basis` to `PageHeader`. The lead that Transit, Progressions, Solar Arc, Composite, Profections, Timing Timeline, Synastry and Primary Directions omit it is **not confirmed**. The fallback headers (for example `TransitView.tsx:305`) omit it on purpose, because no person is loaded.
- **§2 title.** `PageHeader` renders the title as an `h1` (`PageHeader.tsx:21`), or as an `h2` under a page-level `h1` (#1139). The #1059 issue is closed.
- **§6 navigation.** Every `window.location.hash` write in `src/ui` is a select-driven navigation (`AdminNav.tsx:42`, `SectionNav.tsx:66, 96`, `ChartTypeSelector.tsx:37`, `ToolsLayout.tsx:36`) or a redirect after a save (`People.tsx:61`, `PersonForm.tsx:187`, `SetupForm.tsx:59`). The guideline allows both, so no navigating `<button>` was found.
- **§7 loading.** `StatusMessage` sets `aria-busy` for the `loading` and `updating` kinds (`StatusMessage.tsx:14, 35`), so the loading results on `AdminPanel`, `CorpusOverridesPanel` and `CorpusCandidatesPanel` are **Pass**.
- **§8/§9 tables.** A table caption is `h3` by default (`SortableTable.tsx:105`). It is a failure only when no `h2` sits above it under the page `h1`. Chart and consultation tables sit under `h2` section headings, so they pass; the chart and relocated tables not confirmed in a browser are listed below.
- **Rectification §7.** The page shows its states through `StatusMessage`; the `BirthPlaceSearch` dropdown rows (searching, no matches, failed) are a recorded exception (#1162, decision S2, 2026-11-06): they are rows inside a listbox popup with their own spacing and a spinner, not result-region messages, and keep their `status` and `alert` roles. A ratchet test now blocks any new hand-rolled status or alert; the eleven older spots it allowlists are reviewed in #1211.

## Owner decisions needed

These are not filed as failures. Each needs an owner decision before the code can be judged.

1. **Consultation heading omits the person.** `ConsultationView.tsx:473` uses `t.heading` with no subject. Guideline §2 (line 68) asks for "feature and subject". Decide whether the consultation title includes the person.
2. **Home title has no subject.** `Home.tsx:27` uses `t.heading`. Guideline §2 asks for the subject. Decide whether the home title names the last-viewed person, or whether Home is exempt because it is not a person page.
3. **Year and coordinate fields are text fields.** `CyclesView.tsx:403-418`, `EclipsesView.tsx:216-217`, `HoraryView.tsx:164-179`, `ElectionalView.tsx:196-208`, `RectificationView.tsx:257-270` use `TextField` with `inputMode`, not `NumberField`. Guideline §6 names `NumberField` for numeric input. Decide whether year and coordinate inputs are numbers or whether text with `inputMode` is acceptable.
4. **Astrocartography colours.** The hex strokes and hsl sign washes (`app.css:3566-3599`, `app.css:4525-4597`) are chart and visualisation geometry. Guideline §11 exempts chart geometry. Decide whether they stay exempt or must use tokens. Not filed.
5. **Backdrop colours.** `app.css:5723` and `app.css:6146` use `rgb(0 0 0 / 0.45)` for `::backdrop`. No token exists. Decide whether to add a backdrop token or accept the literal.
6. **Shell toggles.** `LanguageToggle.tsx`, `ThemeToggle.tsx`, `SymbolToggle.tsx` and `WorkspaceShell.tsx` use raw `<button>`. Decide whether shell toggles are exempt from the primitive rule (#1161).
7. **Shadow variant.** `app.css:2677` uses `0 0.75rem 1.5rem` where the other literals use `0 0.5rem 1.5rem`. Decide whether it is a separate token or a mistake (#1166).
8. **Safe-area handling.** `src/ui/app.css:7911` is the only use of `env(safe-area-inset-bottom)`. The sticky `.app-header` (`app.css:251`) has no safe-area handling, and `index.html:5` has no `viewport-fit=cover`. Decide whether the app should cover the notch on iOS. Not verified in browser.

## Corrections to the research digest

Recorded so they are not refiled:

- **§7 `aria-busy` (AdminPanel.tsx:383, 462; CorpusOverridesPanel.tsx:396; CorpusCandidatesPanel.tsx:188):** not a failure. `StatusMessage` sets `aria-busy` for the loading kind (`StatusMessage.tsx:14, 35`). `PdfExportBuilder.tsx:526` is a build status with `role="status"`, not a loading state.
- **§2 basis line (#1059 lead):** not confirmed. Every calculated person route above passes `basis` to `PageHeader`. Only the fallback headers omit it, deliberately.
- **§8/§9 tables:** the digest listed the Admin tables (`AdminPanel.tsx`) as heading failures. They pass `headingLevel={2}` (`AdminPanel.tsx:388, 485`). The digest also listed Profections and Periodic Transit tables; both sit under `h2` section headings, so they pass.
- **§6 navigation buttons:** no navigating `<button>` was found. The `window.location.hash` writes are select-driven or redirects after a save.
- **§11 colour literals:** the astrocartography hex strokes and hsl washes are kept out of the failure list and recorded as owner decision 4, as the digest asked.
