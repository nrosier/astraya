# src/ephemeris/ — Map

The Swiss Ephemeris boundary. `sweph-wasm` may be imported only inside this directory
(lint-enforced); everything else talks to the `EphemerisProvider` interface.

### `assets.ts`
**Domain purpose:** Pins the exact Swiss Ephemeris data files, fixed-star catalog and WASM binary Astraya ships, by size and SHA-256, so an upstream repack can never silently change the numbers the app reports. **Responsibility:** Declares the asset list, the shipped date range (1800-2399 CE), and the public URL/mount path the files are served from. **Key dependencies:** No internal imports; consumed by `engine.ts` (which loads these assets into the WASM filesystem).

### `client.ts`
**Domain purpose:** Lets the UI thread call the ephemeris engine without blocking, by proxying every `EphemerisProvider` method across a Web Worker boundary. **Responsibility:** Implements `WorkerEphemerisProvider`, a transport-agnostic request/response client with per-call timeouts and fatal-error latching; spawns the bundled worker. **Key dependencies:** Imports `protocol.ts` (wire types, error (de)serialization) and `types.ts` (`EphemerisProvider` and friends); used by the UI wherever a chart needs ephemeris data off the main thread.

### `engine.ts`
**Domain purpose:** The actual Swiss Ephemeris calculation engine — the only module that touches `sweph-wasm`, which is what keeps the rest of the astrology code engine-agnostic and testable without WebAssembly. **Responsibility:** Implements `SwissEphemerisEngine` (`EphemerisProvider`): initialization, body positions, houses (with polar-latitude fallback and Horizon-system degeneracy detection), ayanamsas, fixed stars, eclipse search, azimuth/altitude, and strict date-range enforcement. **Key dependencies:** Imports `assets.ts` (file list/paths) and `generated-constants.ts` (`SE` flags/ids) and `types.ts`; used directly by `worker.ts` and by tests via `test/engine-harness.ts`.

### `generated-constants.ts`
**Domain purpose:** Supplies the Swiss Ephemeris C library's own numeric constants (body ids, flags, ayanamsa modes, event codes) as read from a live `sweph-wasm` instance, so no value is transcribed by hand. **Responsibility:** Exports the `SE` constant map and `SE_FILES` auxiliary filenames; regenerated by `scripts/gen-constants.mjs` and pinned against the installed package version by a test. **Key dependencies:** No internal imports; consumed by `engine.ts`.

### `protocol.ts`
**Domain purpose:** Defines the wire contract between the UI thread and the ephemeris worker so the two sides of that boundary cannot drift apart. **Responsibility:** Derives `EphemerisRequest`/`EphemerisResponse`/`EphemerisMethod`/`EphemerisResult` types from `EphemerisProvider` via mapped types, and serializes/deserializes thrown errors (including `EphemerisError`'s context) across `postMessage`. **Key dependencies:** Imports `types.ts` (`EphemerisProvider`, `EphemerisError`); used by both `client.ts` and `worker.ts`.

### `types.ts`
**Domain purpose:** Establishes the engine-agnostic vocabulary (`Degrees`, `JulianDayUT`, `BodyPosition`, `HousePositions`, etc.) and the `EphemerisProvider` interface that `src/astrology/**` programs against, deliberately with no mention of `sweph-wasm`. **Responsibility:** Declares every ephemeris data shape and the provider contract every implementation (worker client, direct engine) must satisfy, plus `EphemerisError`. **Key dependencies:** No internal imports; this is the file every other module in `src/ephemeris/` and every ephemeris consumer elsewhere in the codebase imports types from.

### `worker.ts`
**Domain purpose:** Hosts the Swiss Ephemeris engine inside a dedicated Web Worker so a full chart's hundreds of ephemeris calls run off the UI thread, and so the engine's global mutable state (sidereal mode, topocentric observer) stays confined to one serialised request queue. **Responsibility:** Implements `dispatch` (an explicit, exhaustive switch over every provider method) and `serveEphemeris` (wires a worker scope to an engine instance, queuing requests); self-starts only when actually running as a `DedicatedWorkerGlobalScope`. **Key dependencies:** Imports `engine.ts` (`SwissEphemerisEngine`) and `protocol.ts`; the counterpart to `client.ts` across the worker boundary.
